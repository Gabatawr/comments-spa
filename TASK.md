# Тестовое задание: SPA-приложение «Комментарии»

Источник: `docs/source/ТЗ-Комментарии.pdf` (полный текст — `docs/source/task-raw.txt`)
Образцы интерфейса: `docs/task/`

## Суть

SPA-приложение для комментариев. Пользователь оставляет комментарии (см. образец
`docs/task/page1-X10.png`). Все комментарии сохраняются в реляционной БД, включая
данные о пользователе, позволяющие идентифицировать клиента.

## Обязательный стек

- .NET (последняя версия) + Entity Framework
- SQL (MS SQL предпочтительно, допустимы PostgreSQL / SQLite)
- Frontend на выбор: Angular (предпочтительно), React, Vue
- Git, Docker

## Функциональные требования

### Форма добавления записи

| # | Поле | Обяз. | Правила |
|---|------|-------|---------|
| 1 | User Name | да | только латинские буквы и цифры |
| 2 | E-mail | да | формат email |
| 3 | Home page | нет | формат URL |
| 4 | CAPTCHA | да | картинка, цифры и латинские буквы |
| 5 | Text | да | HTML-теги запрещены, кроме разрешённых |

### Главная страница

1. На каждую запись можно написать сколько угодно записей — **каскадное отображение**
   (см. образец: ответы вложены с отступом и левой полосой-цитатой).
2. **Заглавные** комментарии (не являющиеся ответом) выводятся **таблицей** с сортировкой
   по User Name, E-mail и дате добавления — в обе стороны.
3. Пагинация по **25** сообщений на страницу.
4. Защита от **XSS** и **SQL-инъекций**.
5. Сортировка по умолчанию — **LIFO**.
6. CSS-дизайн приветствуется.

### JavaScript и работа с файлами

1. К сообщению можно приложить картинку **или** текстовый файл.
2. Изображение ≤ 320×240 px; изображение большего размера **пропорционально
   уменьшается** сервером. Форматы: **JPG, GIF, PNG**.
3. Текстовый файл ≤ **100 КБ**, формат **TXT**.
4. Просмотр файлов — с визуальными эффектами (пример: lightbox2).

### Регулярные выражения

1. Разрешённые HTML-теги в сообщениях: `a[href,title]`, `code`, `i`, `strong`.
2. Проверка закрытия тегов; код должен быть валидным **XHTML**.

### JavaScript и AJAX

1. Валидация на стороне **сервера и клиента**.
2. Функция **предпросмотра** сообщения без перезагрузки страницы.
3. Панель кнопок для тегов: `[i]`, `[strong]`, `[code]`, `[a]`.
4. Визуальные эффекты приветствуются.

## Требования к результату

- **Развёртывание** (хостинг / VDS) — проверит тестировщик по чек-листу
- **Docker**: приложение в контейнере со всем окружением и зависимостями
- **Git-репозиторий** — будут смотреть историю ветвлений
- **README** — понятно, что за проект и какие функции есть
- **Схема БД** — файл, открываемый в MySQL Workbench, чтобы сравнить проект и реализацию
- **Самопроверка** — поднять проект с нуля строго по README из репозитория

## Уровни (каждый включает предыдущий)

- **Базовый** — всё вышеперечисленное
- **Junior+**: Queue, Cache, Events, WebSocket
- **Middle**: Graph (GraphQL / GraphDb), брокер сообщений (RabbitMQ / Kafka),
  NoSQL (Elasticsearch предпочтительно, Redis, Mongo), Cloud (Azure предпочтительно)
- **Middle+**: архитектура под 1 000 000 сообщений и 100 000 пользователей в 24 часа,
  плюс **нагрузочный тест**

## Область текущей задачи

Цель — довести до **базового уровня + Junior+** целиком и заложить решения под Middle.
Развёртывание на хостинге и облачные сервисы — вне зоны автоматизации: это делается
руками и требует внешних аккаунтов. Docker-упаковка — в зоне.
