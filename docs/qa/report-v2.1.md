## 3. Доказательства по цитатам (функциональная часть)

* `POST` родителя → `quotedText = null`; `POST` ответа → снимок родителя, обрезка по границе слова + `…`.
* Raw `<script>`/`<img onerror>` в тексте → `400 errors.text` (санитайзер), т.е. разметка в снимок не попадает.
* Entity-encoded `&lt;script&gt;` → снимок содержит литерал `<script>…` как **плоский текст**; в DOM —
  текстовый узел, ноль элементов; `alert()` не срабатывает (variant A, зафиксирован §1.1 решений).
* `X-Forwarded-For` сохраняется как есть по контракту `docs/API-v2.md` §6.4 (обрезка ≤64) и рендерится
  интерполяцией — исполнения нет.
* GraphQL `Comment.quotedText`, JSON-ручка `/api/comments/{id}/child` и WebSocket-событие отдают поле
  автоматически (DTO-аддитивность); keyset-пагинация не затронута.
* Независимая состязательная проверка: `docs/qa/verify-v2.1.md` (80/0 DOM, 57/0 API, 20 опасных payload
  против изменённого client-side `sanitize.ts`).

1. **Линия вложенности** 2 px `#e0e2e6` — в образце сплошной линии нет; оставлена по `DESIGN-v2` §5 и

3. **Одна врезка на узел** (снимок родителя) против двух врезок у одного узла в образце. Две врезки —
   два узла (§3.4 решений).
4. **Вертикальный ритм:** блок корня короче образца (~−13 px) из-за метрик шрифта и межабзацных зазоров.
5. **Аватары:** инициалы на цветном круге вместо фотографий (осознанно, §3.6 решений).
6. **Глубина фикстуры:** наш снимок показывает 5 уровней (0–4), в образце видно 3 (0–2).
7. **Вид голосования и глиф ↳** отличаются от типографики образца тоньше/крупнее.

Закрыто CSS-пассом после первого сравнения: белый фон 32 px над шапкой, фон шапки глубины 2

## 5. Известные ограничения и принятые риски

* **Blunt-grep в smoke.** `smoke.sh` ищет `<script` в сыром JSON `/api/comments?pageSize=100`.
  Entity-encoded ввод (плоский `textPlain`/`quotedText`, вариант A) и `clientIp` из `X-Forwarded-For`
  (§6.4, хранится как есть) могут дать ложное срабатывание, если в БД остались adversarial-фикстуры.
  Это pre-existing хрупкость; устранена гигиеной данных: оба adversarial-скрипта
  (`tests/e2e/adversarial.sh`, `tests/e2e/adversarial-quote.sh`) сделаны **самоочищающимися**,
  порядконезависимость `adversarial → smoke` проверена. Сам `smoke.sh` не ослаблялся.
* **Параграфы.** Сервер не разрешает `<p>` (allow-list ТЗ), а новые строки в HTML схлопываются; клиент
  добавляет `<br>` на границах блочных тегов. Многоабзацность достигается только этому; межабзацный
  зазор меньше образца (см. §4.4).
* **Elasticsearch.** Индекс — производное read-модель; удаление строк из БД вручную (очистка фикстур)
  оставляло stale-документы. Удалены (`_bulk delete` по id, которых нет в БД). Приложение не имеет
  ручки удаления, поэтому штатно рассинхрон не возникает.
* **`.work/`** (scratch-харнессы) добавлен в `.gitignore`; в коммит не попадает.
* Данные образца и наши разные (даты/имена/число узлов) — пиксельная разница включает разницу текста;
  геометрия и цвета сверены отдельно (см. `docs/qa/design-v2/README.md` §4).
